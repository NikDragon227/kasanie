# Дорожная карта Kasanie

Живой план. Отмечаем `[x]` по мере готовности. Детали каждого пункта раскрываются, когда до него доходит очередь.

## Принцип очерёдности

Идём по продуктам и кабинетам, сверху вниз по иерархии школьного контура. Каждый предыдущий доводится до состояния «работает и можно не трогать», прежде чем переходить к следующему.

1. **«Спорт рядом» + кабинет организатора** — довести до тихого запуска, дальше только поддержка.
2. **Кабинет владельца школы / академии** (`SchoolOwner`).
3. **Кабинет тренера** (`Coach`).
4. **Кабинет игрока** (`Player`).
5. **Кабинет родителя** (`Parent`).

Фоном, параллельно всем этапам — юридический / ИС / инфраструктурный трек (см. в конце).

> Кабинеты 2–5 уже существуют и работают (фазы 20–22 в `PROJECT_STATUS.md`): школы, команды, составы, журнал тренировки, авто-профиль развития игрока. Здесь речь о доработке и глубине, а не о разработке с нуля.

## Приоритет 1 — «Спорт рядом» + кабинет организатора

Цель: публичный взрослый контур работает целиком, организаторы могут вести регулярные игры, продукт открыт для тихого запуска и после этого только поддерживается.

### 1A. Фундамент (нужен публичному продукту в любом случае)

- [ ] SMTP через VK WorkSpace: ящик на `prokasanie.ru`, DNS (MX `emx.mail.ru`, SPF, DKIM, DMARC), проверить подтверждение почты и восстановление пароля на проде end-to-end
- [ ] `scripts/deploy.sh`: `docker compose up -d --force-recreate` + `docker image prune -f`
- [ ] GitHub Actions: lint + Vitest + xUnit + build на каждый PR
- [ ] Отдельный staging-контур (или хотя бы прогон на локальном compose перед деплоем)
- [ ] Sentry (или GlitchTip) на фронт и бэк + базовые алерты 5xx / latency / диск / БД
- [ ] Ежедневный шифрованный off-site бэкап БД + одно учебное восстановление, retention

### 1B. Полный цикл организатора и гостя проверен на проде

- [ ] Яндекс Карты: `VITE_YANDEX_MAPS_API_KEY` реально в прод-сборке; карта рендерится в списке `/sports` и в выборе точки в кабинете организатора; геокодер определяет район по метке
- [ ] Организатор: регистрация → подтверждение почты → создать площадку по точке на карте → создать активность → опубликовать → список участников → отменить — пройдено руками на боевом
- [ ] Гость: поиск → фильтры → карточка → запись без аккаунта → подтверждение (`.ics` + маршрут) → управление по секретной ссылке → отмена — пройдено руками
- [ ] Запись авторизованного взрослого (18+)
- [ ] Зафиксированы и исправлены баги, найденные при прогоне

### 1C. Фичи, без которых организатор не вернётся

- [ ] «Повторить событие» у организатора (регулярные игры)
- [ ] Управление составом участников у организатора
- [ ] Сохранённые наборы фильтров у гостя
- [ ] Уведомления на почту: новые подходящие события + напоминание перед началом

### 1D. Перед открытием

- [ ] Правила модерации + механизм жалоб
- [ ] Ревизия возрастного шлюза 18+
- [ ] SEO-минимум: пререндер/SSR карточек событий, `sitemap.xml`, `robots.txt`, JSON-LD `SportsEvent`, canonical, OG-теги
- [ ] Реальные площадки и несколько событий в пусковом городе (иначе каталог пустой)
- [ ] Событийная воронка: поиск → карточка → запись, заполняемость, время до первого участника, доля повторов

**→ Тихий запуск. Дальше — только поддержка и мониторинг.**

### 1E. Отложено на потом (не блокирует запуск)

- Площадки: предложения правок, модерация, верификация
- Сообщества: знакомые группы, блокировки
- PostGIS + spatial index (когда поиск по радиусу упрётся в производительность)
- Посадочные страницы «футбол в &lt;город&gt;/&lt;район&gt;»
- Монетизация: платное поднятие карточек, подписка организатора, комиссия за платные события

## Приоритет 2 — Кабинет владельца школы / академии (`SchoolOwner`)

**Есть сейчас:** школа и настройки, команды (создание, назначение тренера), приглашение тренеров по одноразовой ссылке, игроки (создание профиля без самостоятельного входа), базовые показатели школы, изоляция между школами (403 на чужую).

**Доработать:**

- [ ] Дашборд школы: осмысленные метрики (активные команды, заполненность составов, посещаемость по школе, что требует действий)
- [ ] Массовые операции: импорт игроков списком, пакетное создание команд/сезонов
- [ ] Сезоны и архив: переход между сезонами без потери истории
- [ ] Роль `SchoolAdmin`: разграничить, что может админ школы и чего не может (сейчас нав одинаковый с владельцем)
- [ ] Связь родитель ↔ игрок: приглашение родителя со стороны школы, статус согласия на виду
- [ ] Полный CRUD вторичных справочников, которые касаются школы
- [ ] Уведомления владельцу: новый запрос, незаполненный состав, тренер без команды

## Приоритет 3 — Кабинет тренера (`Coach`)

**Есть сейчас:** кабинет по назначенным командам, командный центр, быстрый журнал тренировки (упражнения из каталога, снимок состава, отметка присутствия, матрица «сделал / понял», черновики), самооценка игрока в карточке, тактическая доска, турниры (просмотр).

**Доработать:**

- [ ] Шаблоны занятий: сохранить набор упражнений и переиспользовать
- [ ] Планирование серии тренировок / микроцикл, а не по одному занятию
- [ ] Турнирная заявка: тренер управляет статусом игроков (сейчас частично, добавляет владелец)
- [ ] Массовые действия в журнале (отметить всех, быстрые исключения)
- [ ] Коммуникация: чат с владельцем / командой / родителями — проверить реальную потребность до реализации
- [ ] Мобильный сценарий журнала прямо на поле (крупные тапы, работа при плохой связи)

## Приоритет 4 — Кабинет игрока (`Player`)

**Есть сейчас:** дашборд, профиль, продолжение теста, скоринг, недельный план, воркаут, прогресс, авто-профиль развития (посещаемость, выполнение, понимание, зоны внимания, тренд 12 занятий, история 10 тренировок), субъективная сложность и комментарии к упражнениям.

**Доработать:**

- [ ] UX теста и недельного плана: меньше кликов, понятнее следующий шаг
- [ ] Профиль развития: динамика по навыкам во времени, сравнение с целями
- [ ] Домашние задания от тренера в план игрока
- [ ] Напоминания о тренировке и невыполненном плане
- [ ] Явная пометка «нормативы демонстрационные» пока нет научной валидации

## Приоритет 5 — Кабинет родителя (`Parent`)

**Есть сейчас:** связанные дети, создание профиля ребёнка до 14 лет, просмотр, состояние согласия.

**Доработать:**

- [ ] Уведомления: тренировки ребёнка, обратная связь тренера, важные события
- [ ] Дайджест прогресса ребёнка (регулярная сводка)
- [ ] Жизненный цикл согласия: выдача, отзыв, срок, история
- [ ] Несколько детей в одном кабинете — переключение и общая картина
- [ ] Канал связи с тренером/школой в рамках правил (без медицинских данных)

## Фоновый трек — юридический / ИС / инфраструктура

Идёт параллельно, не блокирует продуктовые этапы, но **152-ФЗ обязателен до открытия «Спорт рядом» для реальных пользователей**.

- [ ] 152-ФЗ: уведомление в РКН как оператор ПДн, политика обработки, формы согласий (родительское для &lt;14), хранение данных россиян на серверах РФ, регламент хранения и удаления
- [ ] Договоры отчуждения исключительного права со всеми, кто что-то создавал (код, дизайн, логотип)
- [ ] Регистрация программы для ЭВМ в Роспатенте (свидетельство + доказательство даты)
- [ ] Товарный знак «Касание» + логотип (после проверки на сходство)
- [ ] Режим коммерческой тайны для непубличных частей (алгоритмы, архитектура)
- [ ] Заменить AI-сгенерированные брендовые картинки на заказные с передачей прав
- [ ] Аудит лицензий зависимостей (MIT/Apache/GPL)
- [ ] SAST / dependency scan / container scan; WAF или Cloudflare перед Nginx; MFA для админов
