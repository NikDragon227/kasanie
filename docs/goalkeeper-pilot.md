# Пилот кабинета тренера вратарей

Статус на 22.10.2026: реализован и показан локально. Пользователь выбрал «Сначала сделать и показать локально». Не выкладывать на production и не назначать production-аккаунт без нового разрешения.

## Как посмотреть

- Локальный интерфейс: http://127.0.0.1:5173/goalkeeper?team=2000&school=2000
- Демо-вход: кнопка «Тренер coach@kasanie.local» на странице входа; пароль подставляется автоматически.
- В локальной «Плазма СПОРТ (локальная проверка)» создано отдельное назначение этого демотренера, два явно помеченных демовратаря, упражнение, завершённые занятия и план будущего занятия. Это не данные production.
- Для назначения через интерфейс: владелец или администратор → «Все команды» → выбрать состав → «Состав» → «Тренер вратарей». Сначала добавьте тренера в школу обычным приглашением, затем назначьте специалистом в нужный состав.

## Возможности

- Отдельный маршрут `/goalkeeper`: обзор, календарь по месяцам/неделям, собственная библиотека упражнений, карточки вратарей и журнал.
- Полный план занятия: дата/время, место, цель, интенсивность, упорядоченные этапы с длительностью и инструкциями, выбранные вратари, посещаемость, необязательные оценки и комментарии.
- Упражнения можно редактировать и архивировать. Сохранённый план содержит снимок описания: редактирование библиотеки не переписывает старые занятия.
- Завершение/отмена подтверждаются внутри кабинета. Завершённые и отменённые занятия не редактируются; их можно скопировать на другую дату с очищенными посещаемостью, оценками и итогом.
- Пересекающиеся по времени вратарские занятия одного тренера запрещены, в том числе между его составами. Сохранение защищено версией и serializable-транзакцией.
- Вратари берутся из активного состава по позиции «Вратарь»/«В»/«ВР»/«GK». Новый вратарь добавляется в общий состав без создания аккаунта и отправки писем.
- Учёт посещаемости считается по завершённым занятиям этого тренера. Личные цели и заметки хранятся отдельно для каждой пары тренер/состав/вратарь.
- Матчи команды показываются только для сведения. Общий календарь, тактика и журнал основного тренера не изменяются.

## Права доступа и хранение

Назначение `GoalkeeperCoachAssignment` отдельно от `TeamCoach`. Самоназначение через API запрещено; назначать и снимать могут владелец, администратор школы и администратор платформы.

Для специалиста без назначения общего тренера применяется членство `GoalkeeperCoach` (новое целочисленное значение 3; существующие значения не меняются). Оно остаётся ограниченным и после снятия назначения. Административное включение/отключение и повторное приглашение не должны незаметно превращать его в обычное тренерское членство.

У владельца и у существующего общего тренера права при дополнительном назначении не меняются. Существующий пилот широких прав обычных тренеров сохранён. При снятии или деактивации назначения доступ к специализированным данным закрывается, история остаётся в базе.

API `/api/coach/goalkeepers/*` требует роль Coach и активное специализированное назначение в активной школе с активным членством. Чужие составы, полевые игроки и библиотека/журнал другого тренера недоступны.

Миграция `20261022100649_AddGoalkeeperCoachPilot`: только четыре новые таблицы, без удаления данных существующих разделов. Применена локально; не применена на production.

## Проверки

- Полный backend-набор: 117 тестов. После уточнения подсчёта специалистов и активных назначений повторно пройдены 35 затронутых тестов школ/кабинета.
- Frontend: 82 теста, lint без предупреждений, TypeScript и production build. Осталось прежнее предупреждение о размере JS-чанка.
- Реальный локальный PostgreSQL: миграция применена, API healthy; модель соответствует миграции.
- Браузер: добавление двух вымышленных вратарей, создание упражнения, сборка трёхэтапного 55-минутного плана, сохранение/повторное открытие, завершение и расчёт посещаемости, копирование на новую дату.
- Текст подсказки в разделе «Турниры» больше не налезает на шапку.
- Мобильный viewport в текущем in-app browser не изменился при запросе; отдельную проверку на реальном узком экране перед production ещё нужно выполнить.

Для запуска тестов в Windows-песочнице полезно задать TEMP/TMP внутри рабочего каталога. Серверному testhost в текущем окружении потребовался запуск вне сетевой изоляции; база тестов остаётся InMemory, без production-запросов.
