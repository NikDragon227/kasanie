# Чек-лист тихого запуска «Спорт рядом»

Выполняется на staging, затем повторяется на production с отдельными тестовыми аккаунтами. Не используйте реальных участников и не публикуйте реальные контакты во время прогона.

## До прогона

- [ ] `scripts/preflight-production.sh` завершился успешно; заполнены рабочие `SMTP_*`, `SMTP_SUPPORT_INBOX` и реквизиты публичных документов.
- [ ] Выполнен свежий проверяемый backup БД; проверка health и контейнеров прошла.
- [ ] Настроен внешний мониторинг `/health/ready`, срок TLS, свободное место, состояние БД и результат backup.
- [ ] В Bugsink создан маршрут уведомления для ошибок уровня Error; проверено тестовым исключением без персональных данных.
- [ ] Уведомление об обработке ПДн, политика, соглашение и правила организатора утверждены владельцем/юристом; ответственный за обращения по ПДн назначен.

## Почта

- [ ] Игрок: регистрация → подтверждение email → вход.
- [ ] Организатор: регистрация → подтверждение email → вход.
- [ ] Восстановление пароля: письмо доходит и ссылка одноразово меняет пароль.
- [ ] Отмена активности: подтверждённый участник и участник листа ожидания с email получают письмо.
- [ ] Продвижение из листа ожидания: после освобождения места письмо приходит новому подтверждённому участнику.
- [ ] Обращение из feedback: создаётся в `/admin/feedback`, уведомление приходит на `SMTP_SUPPORT_INBOX`.
- [ ] На Gmail проверены `spf=pass`, `dkim=pass`, `dmarc=pass` и отсутствие папки «Спам».

## Активности и лист ожидания

- [ ] Организатор создаёт черновик, публикует, редактирует и отменяет активность.
- [ ] Участник записывается на свободное место; счётчик меняется корректно.
- [ ] Следующий участник после заполнения попадает в лист ожидания, а не получает ложное подтверждение.
- [ ] При отмене участия первое место из листа ожидания занимает именно первый ожидающий.
- [ ] Гость без аккаунта получает секретную ссылку и может отменить запись; его контакт не попадает в публичную карточку.
- [ ] Запись несовершеннолетнего на взрослую активность отклоняется.

## Решение о запуске

Запуск разрешён только если все критичные пункты выше закрыты, нет открытых Error в Bugsink, действуют документы и есть ответственный за поддержку. Остальные несрочные UX-улучшения не блокируют тихий запуск, но фиксируются в roadmap.
