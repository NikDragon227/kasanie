# Тренировочный раздел

Маршрут `/coach/trainings?team=<id>` открывает семь разделов: обзор, календарь,
позиционные группы, наставничество, индивидуальные тренировки, отдых и тренеры.
Журнал упражнений и посещаемости сохранён на `/coach/trainings/journal`;
детали занятий по-прежнему находятся на `/coach/trainings/<id>`.

План хранится на сервере в `TeamTrainingWorkspaces`, отдельно для каждой команды.
Кнопка «Сохранить план» сохраняет все разделы; переключение внутренних вкладок
не сбрасывает черновик. При смене года с несохранёнными изменениями запрашивается
подтверждение. Версия плана защищает от перезаписи изменений другого тренера.

Календарь охватывает январь — декабрь выбранного года (2000–2100), с недельным
и месячным представлениями. Каждый день содержит три слота. Матчи из расписания
занимают второй слот; отменённые матчи не блокируют его. Существующие занятия
из журнала занимают свободные слоты по порядку; дополнительные занятия остаются
доступны ссылками. Сервер запрещает менять занятые слоты. Даты учитывают локальный
UTC-сдвиг клиента. Плановые сессии не создают посещаемость автоматически:
конструктор журнала позволяет выбрать упражнения и создать фактическое занятие.

Ответственных и тренерские задачи можно назначать тренерам команды и школы.
Это не предоставляет новых прав доступа. Игроки выбираются только из активного
состава; в наставничестве один игрок состоит в одной группе, наставник входит
в её состав. Индивидуальная позиция, роль, направление, интенсивность, работа
над слабой ногой, комментарий и дата отдыха сохраняются в общем плане.

Риски и рекомендации отображают существующие записи медцентра. Отсутствие
записей не означает медицинского допуска. Интенсивность календаря — ориентир
плана относительно 90 минут матча; нагрузка тренера — число назначенных
направлений. Рейтинги, удовлетворённость и медицинские показатели не генерируются.
Разбивка сессий считается по запланированным минутам текущей недели, без матчей
и отдыха. Комментарии об удовлетворённости и подготовке вводит тренер.

Миграция: `20261014082020_AddTeamTrainingWorkspace` (создание одной таблицы,
без изменения существующих тренировок). При деплое применяется автоматически
на старте API; перед обновлением необходимо сделать резервную копию базы.

Проверки: `pnpm run lint`, `pnpm test`, `pnpm run build`; `dotnet test
backend/Kasanie.Tests/Kasanie.Tests.csproj`. Тесты проверяют сохранение разделов,
версионный конфликт, доступ к команде, чужие назначения, занятые слоты,
локальные даты, календарные границы, группы и тренерские задачи.
